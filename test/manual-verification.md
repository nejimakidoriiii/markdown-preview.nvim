# Issue #1 手動確認手順（REQ-ID 別）

プレビュー内の Markdown リンクを独立したプレビューで開く機能の、REQ-ID ごとの手動確認手順。

- 自動テストフレームワークの導入は利用者決定により本 Issue の対象外である（`specs/1/requirements.md` の「対象外」、`specs/1/trace.md` の「検証の対象外と判断した形式」）。したがって確認は本手順に従い、実ブラウザと実エディタで行う。
- 本手順の「契約」は `specs/1/requirements.md` の REQ-ID の観測可能な条件である。手順は対応する Gherkin シナリオ（`specs/1/gherkin/markdown_link_preview.feature`）の受入条件に一致させる。
- 用例の所在: `test/test.md` の「Markdown リンク確認用（Issue #1）」節。リンク先フィクスチャは `test/` 配下とリポジトリ直下の `up.md`。

## 共通準備

1. 既存 lockfile（`yarn.lock`）に従って依存関係を導入し、TypeScript と Next の成果物を生成する（`npm run build-lib`、`npm run build-app`）。Node 17 以降では Next ^7.0.2 の webpack が `ERR_OSSL_EVP_UNSUPPORTED` で失敗するため、`NODE_OPTIONS=--openssl-legacy-provider npm run build-app` を使う。
2. エディタは Neovim は `nvim`、Vim は `/usr/bin/vim` を使う。`vim` コマンドは Neovim であるため、Vim の確認に代用しない。
3. 大小文字の確認（sub.md と sub.MD の共存）は、大小文字を区別するファイルシステム（Linux）で行う。
4. REQ-007・REQ-008・REQ-018（読込失敗）の実体を次のコマンドで作成する。`/tmp/mkdp-dir-target.md` は拡張子が `.md` の読取可能なディレクトリであり、アクセス権確認だけでは検出できない読込失敗（起動前の実読込）の確認に使う。

```sh
printf '# mkdp absolute target\n' > /tmp/mkdp-absolute-target.md
printf 'unreadable\n' > /tmp/mkdp-unreadable.md
chmod 000 /tmp/mkdp-unreadable.md
mkdir -p /tmp/mkdp-dir-target.md
```

5. `test/test.md` を開き `:MarkdownPreview` を実行して元プレビューを表示してから、各手順に入る。

## 実装前の失敗基線

実装前は、相対 Markdown リンク（例: `[a](sub.md)`）のクリックは既存動作どおり 404 になる（`app/routes.js` のページ経路は `/page/<数値>` のみ受理）。この状態が実装前の失敗基線であり、実装後に REQ-002 の挙動へ変わることを確認する。

## REQ-001 対象拡張子（.md / .markdown、大小文字を区別しない）

- 操作: 「対象リンク」節の a（sub.md）、b（sub.markdown）、MD（sub.MD）、Markdown（sub.Markdown）、c（UPPER.MD）を順にクリックし、最後に引用内の d（sub.md）をクリックする。
- 契約: 各クリックごとに独立した新規プレビューが開き、クリックしたリンク先のファイル内容が表示される。引用内のリンクも対象である。
- 判別: 各リンク先ファイルの見出しにファイル名があるため、表示された内容から拡張子・大小文字の解決結果を直接判別できる。
- 誤実装の検出: リンクテキストの字面だけで対象を判定する実装は、sub.MD・sub.Markdown・UPPER.MD の大小文字の扱いを誤る。

## REQ-002 クリックで独立プレビューを開く

- 操作: `[a](sub.md)` をクリックする。
- 契約: 元のプレビュー（test.md のページ）は閉じず・遷移せず残り、別のタブまたはウィンドウでリンク先のプレビューが開く。

## REQ-003 再クリックで毎回新規に開く

- 操作: `[a](sub.md)` を 2 回クリックする。
- 契約: 2 つの独立したプレビューが存在する。既存ページの再利用（同一タブの再読み込みや切替え）が起きていないことをタブ・ウィンドウの一覧で確認する。

## REQ-004 combine の影響を受けない

- 操作: `[a](sub.md)` をクリックする。

- 後片付け: `:let g:mkdp_combine_preview=0`

## REQ-005 対象外リンクの既存動作を維持する

- 操作と契約（それぞれ独立プレビューを開かないこと）:
  - `[外部](https://example.com/)` → ブラウザによる外部遷移。
  - `[見出し](#section)` と `[sub.md](#section)` → 同一ページ内の見出し Section へのスクロール。リンクテキストに .md を含む後者でも対象と誤判定しない。
  - `[データ](./data.txt)` と `[sub.md](./data.txt)` → 従来どおり 404 表示。
- 追加操作: 「コード文脈」節の各表示（インラインコード、インデントコード、3 個と 4 個のバッククォートフェンス、チルダフェンス、引用内フェンス、HTML コメント、エスケープされた角括弧）をクリックする。
- 契約: いずれのクリックでも独立プレビューが開かない。HTML コメントは表示されず、エスケープされた角括弧は文字どおり表示される。
- Windows の対象外: `[絶対WinTXT](C:/docs/target.txt)`（ドライブ絶対パスの non-md）をクリックする。独立プレビューを開かず 404 となる。`[外部](https://example.com/)` はドライブパスの受理と同じ入口を通るため、外部 URL がローカル対象に化けていないことをこの 2 つの組で確認する。
- 独立ページ内の対象外リンク: `[a](sub.md)` の独立プレビューを開き、そのページ内の `[data](./data.txt)` をクリックする。遷移先が 404 となりプレビュー画面（`pages/index.js` を読み込むページ）を返さないこと。HTTP 応答の確認は `curl -i http://localhost:<ポート>/file/data.txt`（404）と `curl -i http://localhost:<ポート>/file/sub.md`（200 のプレビューページ）で行う。独立ページの基準ディレクトリで解決される `./data.txt` は `test/data.txt` であり、`GET /data.txt` だけの確認ではルートの一致を代弁しない。

## REQ-007 絶対パスをそのまま解決する

- 操作: `[絶対 /tmp/mkdp-absolute-target.md](/tmp/mkdp-absolute-target.md)` をクリックする。
- 契約: `/tmp/mkdp-absolute-target.md` の内容が表示される。リンク元ディレクトリの付加（`test/tmp/...`）が起きていないことを表示内容で確認する。
- Windows のドライブ絶対パス: Windows で事前に `C:\docs\target.md` を作成する（`# absolute target` の見出しを含む別ファイルでもよい）。`[絶対Win](C:/docs/target.md)` をクリックする。リンク元ディレクトリ（D ドライブ側など）を付加せず、`C:/docs/target.md` の内容を独立プレビューで表示する。Markdown の href にバックスラッシュで `[絶対Win](C:\docs\target.md)` と書いた場合も同じ結果になることを確認する。
- 独立ページからの絶対パス: `[a](sub.md)` の独立プレビューを開き、そのページ内の絶対パス指定（Windows では `C:/docs/target.md`、それ以外では `/tmp/mkdp-absolute-target.md`）をクリックする。独立ページ自身のディレクトリではなく、指定パスをそのまま解決した内容が表示される。

## REQ-012 / REQ-014 / REQ-015 ディスク表示と取得元の切替（同一ページで連続確認）

この 3 つの契約は、同じブラウザページを開いたまま変化の前後を一続きに観察する。手順の途中でページを作り直さないこと。

1. （REQ-012）`:ls` で disk.md がバッファリストに存在しないことを確認する。`[disk](disk.md)` をクリックする。disk.md の内容が表示される。直後に `:ls` とエディタのウィンドウ構成が変化していないこと（バッファ作成・画面切替の拒否）を確認する。
2. （REQ-014 前半・同じページ）シェルから `test/disk.md` に追記する。プレビューの表示は開いた時点の内容のままであること（外部編集で自動更新されないこと）を確認する。
3. （REQ-014 後半・同じページ）ブラウザの再読み込みを行う。表示がディスクの最新内容になることを確認する。
4. （REQ-015・同じページ）エディタで `disk.md` を開き、未保存の編集を行う。カーソル移動などで更新機会を作る。同じページの表示が、未保存編集を含むバッファの内容に切り替わることを確認する。初回の取得元（ディスク）に固定される誤実装はこの手順で失敗する。

## REQ-017 アンカー付きリンクの見出し位置を表示する

- 操作: `[アンカー付き sub.md#section](sub.md#section)` をクリックする。
- 契約: sub.md の独立プレビューが開き、見出し Section が表示範囲に入る。Section より前のスクロール確認用の行が画面上端より上にあり、先頭位置のままでないことで移動を判別する。
- 参考: `[見出し](#section)`（アンカーのみ）は REQ-005 どおり同一ページ内移動であり、独立プレビューを開かない。
- 日本語見出し: `[日本語](sub.md#%E6%97%A5%E6%9C%AC%E8%AA%9E)` をクリックする。独立プレビューで見出し「日本語」が表示範囲に入る。見出し id はレンダラーがパーセント符号化して生成するため、検索前にフラグメントをデコードする実装はこの手順で失敗する。
- 日本語と記号の混在見出し: `[日本語!](sub.md#%E6%97%A5%E6%9C%AC%E8%AA%9E!)` をクリックする。独立プレビューで見出し「日本語!」が表示範囲に入る。起動用のフラグメントは `!` が `%21` へ追加符号化されるが、レンダラーが生成する id は `!` を保持するため両者の文字列は一致しない。デコードした見出し指定をレンダラーと同じ符号化へ戻す検索を挟まない実装はこの手順で失敗する。
- フラグメントと表示文字列の分離: `[日本語!](sub.md#%E6%97%A5%E6%9C%AC%E8%AA%9E)` をクリックする。移動先は見出し「日本語」であり、リンクの表示文字列「日本語!」を見出し指定に使わない。
- 誤りのフラグメント: `[日本語](sub.md#section)` をクリックする。移動先は Section であり、リンクテキストの「日本語」を見出し指定に使わない。
- HTML アンカー: 「HTMLアンカー」節の `html-section`（`<a href="sub.md#section">`）をクリックすると Section へ移動する。`html-pipe`（`<a href="sub.md#section|mkdp-fragment">`）ではパイプが命令として解釈されず、見出し「Section|mkdp-fragment」が移動先になる。
- 初回移動の後: 同じ独立プレビューを開いたままエディタでカーソルを移動して更新機会を作る。以後は既存の同期スクロールに従い、初回の見出しへ戻らないこと（初回アンカーの消費）。

## REQ-018 不在・読込失敗を元画面に表示する

- 操作: `[不在](missing.md)` をクリックする。
- 契約: 元のプレビュー画面上にエラーが表示され、新しいプレビューのタブ・ウィンドウが開かない。読み込み成功後の起動を待たず空ページを開く誤実装は、この手順で検出される。
- 読込失敗: 共通準備の `/tmp/mkdp-unreadable.md`（chmod 000）に対する `[読込失敗](/tmp/mkdp-unreadable.md)` をクリックし、同じ結果を確認する。確認後 `chmod 644 /tmp/mkdp-unreadable.md && rm /tmp/mkdp-unreadable.md` で片付ける。
- 読取可能なディレクトリ: 共通準備の `/tmp/mkdp-dir-target.md`（.md 拡張子の読取可能なディレクトリ）に対する `[読込失敗 dir](/tmp/mkdp-dir-target.md)` をクリックする。アクセス権の確認は通るため、実際の内容読込に失敗した時点で元画面にエラーを表示し、新規プレビューを開かないこと。確認後 `rm -rf /tmp/mkdp-dir-target.md` で片付ける。

## REQ-019 独立プレビューからも再帰的に開く

- 操作: `[再帰 inner](inner/inner.md)` をクリックし、開いた独立プレビュー内の `[inner2](inner2.md)` をクリックする。
- 契約: `test/inner/inner2.md` がさらに独立した新規プレビューで開く。基準ディレクトリは直前のリンク元（`test/inner/inner.md`）であり、最初の元ファイル基準（`test/`）と誤ると `test/inner2.md` を探してエラー表示になるため、この用例で基準の誤りを検出できる。
- 参考: sub.md の独立プレビュー内の `[nested](nested.md)` も同様に開く。

## REQ-020 終了時に独立プレビューも閉じる

停止は 3 つの監視状態（リンク未使用、バッファ由来リンクのみ、ディスク由来リンク使用後）のそれぞれで完走を確認する。監視グループが未作成の状態での解除が停止処理を中断させる誤実装は「リンク未使用」と「バッファ由来のみ」の手順で検出される。

1. （リンク未使用）`test/test.md` で `:MarkdownPreview` を実行し、リンクを 1 つもクリックしないまま元プレビューを開く。`:MarkdownPreviewStop` を実行する。元プレビューが閉じること。
2. （バッファ由来のみ）`sub.md` を開き `:MarkdownPreview` で元プレビューを表示し、`[a](sub.md)` だけをクリックして独立プレビューを開く（ディスク取得のリンクはクリックしない）。`:MarkdownPreviewStop` を実行する。元プレビューと独立プレビューが閉じること。
3. （ディスク使用後）元プレビューに加え、`[a](sub.md)`（バッファ取得）と `[disk](disk.md)`（ディスク取得）の独立プレビューを開く。`:MarkdownPreviewStop` を実行する。元プレビューとすべての独立プレビューが閉じる。ディスク取得のページだけが管理外に残る誤実装は、この手順で検出される。
4. （Toggle 停止側）`:MarkdownPreviewToggle` で開始し、独立プレビューを開いた後、再度 `:MarkdownPreviewToggle` を実行する。全プレビューが閉じ、停止状態へ戻ること。
5. （VimLeave）独立プレビューを開いた状態でエディタを終了する（`:qa!`）。終了処理の中で全ページへ close が配信され、プレビューが閉じること。Stop の結果だけで代用しない。

## REQ-021 元プレビューの表示・更新・終了を維持する

- 操作: リンク開封後にエディタで `test/test.md` を編集し、カーソル移動などで更新機会を作る。
- 契約: 元プレビューが従来どおり自動更新される。リンク開封が元の更新配信を壊していないことを確認する。終了の維持は REQ-020 の手順で確認する。

## REQ-022 Neovim と Vim の両方で動作する

- 操作: Neovim で REQ-010（バッファ経路）と REQ-012（ディスク経路）を実施した後、`/usr/bin/vim` で同じ 2 経路を実施する。停止の 3 状態（REQ-020 の 1〜3）も両エディタで実施する。
- 契約: 両エディタでバッファ取得・ディスク取得の両経路が動作し、3 つの監視状態のいずれでも停止が完走する。Vim 専用の別規則や Vim 非対応 API への依存は、この手順で検出される。

## REQ-023 確認用リンク用例の追記

- 確認: `test/test.md` に相対・絶対・アンカー付き（英字・日本語・記号混在・パイプ付き見出し、HTML アンカー）・不在・読込失敗・対象外のリンク用例が存在すること。リンク先ファイルのうち `missing.md` と `/tmp` の 3 つと `C:/` の 2 つ（Windows 実行時のみ実在を作成する）を除くすべてが実在すること（`missing.md` は不在を期待値とするため作成しない。`/tmp` の実体は共通準備の手順で作成する）。

```sh
ls test/sub.md test/sub.markdown test/sub.MD test/sub.Markdown test/UPPER.MD test/nested.md test/disk.md 'test/my file.md' 'test/my%20file.md' test/data.txt test/inner/inner.md test/inner/inner2.md test/img/sample.svg up.md
test ! -e test/missing.md
grep -c 'sub.md#%E6%97%A5%E6%9C%AC%E8%AA%9E' test/test.md
grep -c 'sub.md#%E6%97%A5%E6%9C%AC%E8%AA%9E!' test/test.md
grep -c '# 日本語!' test/sub.md
grep -c 'C:/docs/target.md' test/test.md
grep -c 'href="sub.md#section|mkdp-fragment"' test/test.md
grep -c '# Section|mkdp-fragment' test/sub.md
```
